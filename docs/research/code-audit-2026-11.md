# Audit del codice Counselorbot (main 39257a0b) — sola lettura

## Verdetto

Il codice è in condizioni migliori di quanto il volume di PR di oggi farebbe temere: le autorizzazioni sulle rotte di classe (`backend/routes/groups.py`, `practice_notebooks.py`) sono coerenti, il Markdown della chat non accetta HTML grezzo, gli import `.ts` nei test sono tutti protetti da `// @ts-expect-error`, e non ci sono TODO/FIXME che nascondono problemi.

I problemi veri sono tre:

1. **Il default Python 3.10 del Dockerfile non può avviare il backend** (il codice importa `datetime.UTC`, che esiste da Python 3.11). La produzione su questo Mac funziona solo perché `.env` forza `python:3.12-slim`; `docker-compose.yml` e la guida di installazione portano ancora a 3.10.
2. **La pagina classe smonta tutto a ogni ricarica dei dati**: cambiare la copertina (o qualunque `reload`) butta via senza avviso la bozza non salvata degli strumenti. È il bug sospettato in `ClassSettingsPage`, confermato.
3. **La CI del frontend non compila né esegue i test**: solo i18n (16 moduli su 69) ed ESLint con 78 errori tollerati. Un errore di tipo arriva fino al build Docker di produzione.

Il resto è igiene: vincoli mancanti, validazione di `image_url`, N+1 sulla scheda studenti, file morti dopo il refactor.

### Cosa NON è stato verificato

Audit statico, senza eseguire test, build o server. Non coperti in profondità: `chat_logic.py`, `ai_service.py` e le chiamate ai provider (SSRF su `ollama_ip`, `llamacpp_url`, `omniroute_url`, API personali: non verificato), forum, `class_paths.py`, rotte `goals.py`, pannelli admin. Le rotte senza dipendenza di autenticazione sono state elencate tutte in modo automatico e controllate una per una solo per `memory`, `pqbl`, `prompt_experiments`, `groups`.

### Verificato e senza problemi

- **TS5097**: nessun import di valore con estensione `.ts` privo di `// @ts-expect-error` in `frontend/src`.
- **XSS**: `ToolIllustration.tsx` inserisce solo stringhe statiche di `lib/tool-illustrations`; `ChatMarkdown` e `ForumView.tsx:26` non accettano HTML grezzo; `DiagramViewport.tsx:182` inserisce SVG prodotto da Graphviz con etichette passate da `_xml_escape` (`backend/diagram_render.py:560-625,885`).
- **Autorizzazioni di classe**: inviti, note, risultati, conversazioni, noticing e quaderni di prova passano tutti da `_require_visible_group` / `_owned` e, dove serve, da `authorize_data_access`. Nessun IDOR trovato nelle rotte lette.
- **Persistenza copertine**: `class_images` sta sotto `/app/uploads`, che è un volume in entrambi i compose.
- **Segreti**: nessuna chiave nel codice letto; `.env` non è tracciato.
